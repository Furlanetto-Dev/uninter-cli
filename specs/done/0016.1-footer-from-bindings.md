# The footer, and the keys come from the bindings

## TL;DR
- `components/footer.py` holds the app's `Footer`; all four screens compose it, `ConfirmStart` and `ConfirmReset` included.
- A key shows only when it is the key that fires; when a Textual widget owns it, our subclass re-declares the same action with a description instead of the screen mirroring it.
- `check_action` decides when a key is pressable, so the footer never names one that would do nothing.
- Binding descriptions are screen text: Portuguese, lowercase.
- Nothing else prints a key: the `⏎ apagar    esc cancelar` line inside `ConfirmReset`'s prompt goes, and so does the `⏎` in `NEVER_SYNCED`.

Two of the four screens have a footer and two do not, so a modal teaches its keys in prose that drifts from its own `BINDINGS`: `ConfirmReset` spells its two keys twice, once as text and once as bindings, and `ConfirmStart` ([0014](../done/0014-atividade-start-confirmation.md)) shows none of its three. Part of [0016](0016-cli-components.md); the screens are in [0004](../done/0004-textual-tui.md).

## Observed behaviour
- Textual's `Footer` composes from `screen.active_bindings`, keeping what has `show=True` and dimming what `check_action` disabled — the key list is already derived, never written.
- `active_bindings` walks `_modal_binding_chain`, which stops at the last modal, so a footer inside `ConfirmStart` or `ConfirmReset` lists that modal's keys and not the app's `r`, `q`, `j` and `d`.
- `_merge_bindings` walks the MRO base first and lets a subclass replace the whole entry for a key, so re-declaring `enter` with the inherited action and a description is enough to make it show.
- `ProvaScreen` already shadows `q`, `r` and `j` with an empty binding and the footer drops them there; it also groups `pageup` and `pagedown` under one visible `rolar`. The screen already decides what is pressable — nothing else needs to.

## Decisions

### A shown key is a key that fires
Mirroring a widget's key on the screen would put an entry in the footer that is not what runs — the reason [0004](../done/0004-textual-tui.md) kept `⏎` out of `BINDINGS`. Re-declaring it on our own subclass keeps the firing action and gains the description: `⏎ buscar no AVA` on `MateriaList`, `⏎ iniciar` on `AtividadeTree`, `⏎ escolher` on the answers of `ConfirmStart`. This supersedes that note in 0004.

### `check_action` decides when a key is pressable
`⏎` on `MateriaList` only fetches while the matéria was never synced, and on `AtividadeTree` only a leaf starts a prova. Both answer through `check_action`, the guard the app already uses for `j`, so the footer names the key exactly when pressing it does something. `NEVER_SYNCED` then drops the key and says only that the matéria was never synced.

### The arrow steps stay hidden
`left`, `right` and `up` carry the name of the pane they land on, not an action. They stay `show=False`: the arrows are self-evident, and four more entries would bury `⏎` and `esc`.

### Descriptions are Portuguese
They are screen text, so [0009](../done/0009-english-code-portuguese-domain.md)'s rule applies: `r atualizar`, `q sair`, `d início`, `esc voltar`, `ctrl+c copiar`. Half of them are English today.

## Rejected
- **A footer that builds its own key list.** A second truth next to `BINDINGS`, which is the drift this spec removes.
- **Textual's `Footer` imported in four places.** Nothing to change in one place when the house style moves, and nothing to grep.
- **Teaching `⏎` in the empty-state hint as well as in the footer.** Two places saying the same key is where this started.

## What execution corrected
- **`⏎ iniciar` on `AtividadeTree` was dropped.** `Tree.auto_expand` is `True`, so `enter` on a group collapses it — verified by pressing it. Re-declaring the key with a `check_action` that hides it on groups would disable it there too, leaving a choice between a footer that lies and a key that broke. The tree keeps Textual's hidden binding; `⏎` there is two actions and no single description is true of both.
- **The modals were worse than observed.** They do not merely lack a footer: the screen underneath paints its own through them, so both modals advertised `r refresh`, `q quit` and `d home` while none of the three could fire. The before capture shows it.
- **`MateriaList` had to be told which collection is active.** Whether `⏎` fetches depends on the open tab, so the list holds the collection, the app sets it on tab change, and `synced_at` moved next to it. Verified across four states: the key appears only when the highlighted matéria has that collection unsynced.
- Two `refresh_bindings()` calls keep the guard current — on the list's own highlight message, and after a sync redraws a matéria. Without them the footer holds a stale key until focus moves.
- `ConfirmStart`'s `left` and `right` became `show=False` under this spec's arrow rule, leaving its footer reading `⏎ escolher  esc não`.
