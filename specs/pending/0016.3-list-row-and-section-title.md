# The row and the section title of a list

## TL;DR
- `components/row.py` holds `row_grid(mark=False)`, returning the configured `Table.grid`, and `section_title(text)`, returning the dim disabled `Option`.
- `materias/list.py` and `provas/list.py` call them; each keeps its own `add_row`, so the matéria's three cells and the questão's two lines stay where they are.
- The mark column is a flag, not a second function: it is the only difference between the two grids today.

Both lists arrived at the same grid by being written next to each other, and the next list will arrive at it by being written next to one of them. Part of [0016](0016-cli-components.md).

## Observed behaviour
- `materias/list.py::_row` and `provas/list.py::_grid` both call `Table.grid(expand=True, padding=(0, 1))`, then an ellipsis column with `no_wrap=True, ratio=1`, then a right-aligned `no_wrap` column. The matéria grid inserts a `width=1` column between them for the sync mark.
- `materias/list.py::_title` and `provas/list.py::title_row` are both `Option(f"[dim]{…}[/dim]", disabled=True)`, one per section heading.
- The questão row calls `add_row` twice on one grid, for the preview and the answer under it; the matéria row calls it once. The grid is shared, the filling is not.

## Decisions

### The component returns the grid, not the row
`row_grid` configures the columns and hands the grid back; the caller adds its own cells. A `row(text, mark, value)` that took the cells would have to grow a second signature the moment a caller wants two lines, which one already does.

### The mark column is a boolean argument
Two callers, one difference. A flag reads at the call site — `row_grid(mark=True)` — and a second function would leave two places to change when the padding moves.

### `section_title` goes with the row, not with the list
A heading is a row of the list that happens to be disabled, and it is dim for the same reason the period is. Splitting them across two modules would split the two halves of one look.

## Rejected
- **A `Row` widget.** The rows are Rich renderables inside `Option`s, not widgets; making them widgets would cost the ellipsis and the alignment the grid gives for free.
- **Waiting for a third caller.** The shape is already duplicated, and the third caller is the one that copies whichever version it finds first.
