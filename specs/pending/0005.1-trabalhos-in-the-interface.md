# Trabalhos in the interface

[0005](../done/0005-trabalhos.md) stopped where it said it would: crawler and api complete, verified against the real AVA, without touching the interface. The result is that today `TrabalhoSyncService` exists, works and **nobody calls it** — it is not wired in the composition root, because wiring it without a consumer produces dead code.

This spec covers the two loose ends: getting the trabalho onto the screen, and obtaining the two endpoints 0005 could not reach. What the project is lives in [CONTEXT.md](../../CONTEXT.md), the interface in [0004](../done/0004-textual-tui.md) and the trabalho model in [0005](../done/0005-trabalhos.md).

## Observed behaviour

- **The service is ready and switched off.** `TrabalhoSyncService.sync(materia)` walks the whole cascade and writes the three tables in one transaction. Checked on four matérias: 0, 1, 4 and 4 trabalhos, with entregas and etiquetas. Only the line in `main.py` is missing.
- **The AVA screen has six links, and two have no captured endpoint.** Etapa details, entrega details, the correction block and correction details come out of what is already in the database. `ANEXOS(n)` and `Gabarito` do not: for the first we only have the `totalArquivosEntrega` counter, for the second nothing.
- **The etiqueta text is HTML.** It comes with `<br />` and entities like `&gt;`, and runs past a thousand characters in long feedback. We store it raw, so whoever displays it has to decide what to do with it.
- **13 of the 26 matérias have no trabalho at all.** Any spot the screen reserves for trabalhos sits empty in half the matérias.

## Decisions

### The service is only wired when something calls it

Until the interface consumes trabalhos, `main.py` does not wire `TrabalhoSyncService`. Wiring it earlier produces a variable that exists only to be discarded, and pyright in strict mode flags it. The line goes in together with the consumer, in the same step.

### The captures come before any attachment modelling

This project does not hunt for endpoints. Without the `ANEXOS` and `Gabarito` curls captured in DevTools, there is no DTO, table or request for them — 0005 already records both as pending, and here they are a prerequisite, not an optional task.

## What is still undecided

Where and how the trabalho appears in the TUI. [0004](../done/0004-textual-tui.md) fixed a single screen, with the matérias list always visible and a detail panel on the right; trabalho is a second collection of the same matéria, and it has no reserved spot. The open questions:

- Where the trabalho appears: decided in [0011](0011-tabbed-detail-panel.md) — a tab of its own in the detail panel — and detailed in [0011.1](0011.1-trabalhos-tab.md).
- Does trabalho join the same background sync queue of [0007](../done/0007-background-queue-and-reset.md), or only on demand?
- Does the tutor's feedback, which is long HTML, fit in the panel or call for a screen of its own?

None of this is decided here on purpose: they are interface choices that call for discussion before becoming a written decision.

## The tasks

**Unblocking**

1. Capture in DevTools the `ANEXOS(n)` curl and the `Gabarito` one, and save them in `uninter-endpoints/trabalhos/` with the cookie replaced by a placeholder.

**Interface**

2. Decide the shape of the screen (the questions in the section above).
3. Wire `TrabalhoSyncService` in the composition root of `main.py`, together with the consumer.
4. Display the trabalhos of the focused matéria, including the empty state of the 13 matérias with no trabalho.
5. Display the entrega and correction of the selected trabalho, resolving the feedback HTML.

**If the captures come through**

6. DTO, request and table for attachments.
7. The same for the answer key.

## Rejected

- **Wiring the service now, with the consumer later.** Leaves `main.py` with a discarded variable and pyright complaining, in exchange for nothing: the line costs the same written today or together with the screen.
- **Inferring the attachment URL from the pattern of the other endpoints.** The three trabalho endpoints follow shapes that differ from one another (`TrabalhoEtapa/{oferta}`, `TrabalhoEntrega/{etapa}/GetByEtapaUsuario/{vinculado}`, `TrabalhoCorrecaoEtiqueta/{correcao}`). There is no pattern to deduce from, and guessing means hitting the university's server until something sticks.
- **Converting the feedback HTML in the crawler.** The layer that talks to the AVA stores what the AVA sent. Whoever displays it decides whether it becomes plain text, markdown or rendered.
