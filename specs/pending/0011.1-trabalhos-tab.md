# Trabalhos tab

## TL;DR
- Second `TabPane#trabalhos`, "2 Trabalhos", with `TrabalhoTable`: one row per `Trabalho`, ordered by `ordem` — Trabalho, Entrega, Nota, Situação, Prazo — and a hint for the empty states.
- `TrabalhoSyncService` reaches parity with `AtividadeSyncService`: `TrabalhoRequest.fetch` returns a `FetchResult`, the list response is stored as one `Captura` under `TRABALHOS`, and the database phase runs under `asyncio.shield`. `main.py` mounts it in the same change.
- The sweep of 0007 loads every matéria's atividades first, then every matéria's trabalhos; opening the tab on a matéria never synced fetches it at the front, under the loading wave. Queue items become (matéria, collection).
- Keys mirror the atividades table: `→` in from the list, `←`/`esc` out, `→` at the edge into the debug panel; `focus_pane` dispatches on the active pane.
- The `●` mark on the list means "the sweep has not finished this matéria": either stamp missing. Debug follows focus: the matéria while the list has it, the row under the cursor while a pane's table has it.

[0005](../done/0005-trabalhos.md) left the trabalhos in the database and [0005.1](0005.1-trabalhos-in-the-interface.md) left them off the screen; [0011](../done/0011-tabbed-detail-panel.md) gives them a place, and this spec fills it. Context in [CONTEXT.md](../../CONTEXT.md); names in [0009](../done/0009-english-code-portuguese-domain.md).

## Observed behaviour
- `Trabalho` has `nome`, `tipo`, `ordem`, `fim`, `entregue_em`, `nota`, `aprovado` (tri-state) and `pode_entregar`; the row needs nothing from `TrabalhoEntrega`. `TrabalhoRepository.list_all(materia)` already exists. Read in `api/trabalhos/`.
- 13 of 26 matérias have no trabalho, and each sync is a three-request cascade ([0005](../done/0005-trabalhos.md), [0005.1](0005.1-trabalhos-in-the-interface.md)).
- `trabalhos_sincronizados_em` is a stamp of its own on `Materia`, with `mark_trabalhos_synced` beside it ([0005](../done/0005-trabalhos.md)).
- `TrabalhoSyncService` predates 0010: no `Captura`, no shield, and its three requests return bare lists. Read in `api/trabalhos/service.py` and `crawler/trabalhos/request.py`.
- `Captura` is one row per (`recurso`, `materia_id`) — `CapturaRepository.replace` deletes by that pair — so per-trabalho entregas do not fit the key. Read in `api/capturas/`.
- `Widget.loading` covers the widget's own region with `get_loading_widget()`, and a `TabPane` whose children are hidden is one row tall; with a `min-height` of 7 the `Loading` wave measures 7 rows. Checked with `run_test`.
- Since 0011, `focus_pane` falls back to the list for any pane but atividades, and `DebugPanel.show`, `meta_text` and `field_rows` are typed for `Atividade`. Read in `cli/`.

## Decisions

### One row per trabalho, five columns, no entregas
Trabalho (`nome`), Entrega (`entregue_em` as `dd/mm/aa`, "—" before delivery), Nota, Situação (`aprovado` true → green "aprovado", false → red "reprovado"; `None` → dim "em correção" once delivered, yellow "aberta" while `pode_entregar`, dim "não entregue" otherwise), Prazo (`fim`, coloured as in [0006](../done/0006-deadline-and-media-colour.md)). `format_deadline`, `is_overdue` and `format_number` are reused. Entregas and etiquetas need a detail view, not a column.

### The service reaches parity with atividades: result, one capture, shield
`TrabalhoRequest.fetch` returns a `FetchResult` carrying the response; `EntregaRequest` and `EtiquetaRequest` keep returning lists. `_store`, under `asyncio.shield`, writes trabalhos, entregas, etiquetas, one `Captura` under `TRABALHOS` for the matéria, and the stamp, in one commit — the shape `AtividadeSyncService` has had since [0010](../done/0010-debug-mode.md). Only the list is captured because `Captura` is keyed by matéria; what entregas and etiquetas need is decided with the view that shows them.

### The sweep loads atividades first, then trabalhos, through the same consumer
Queue items become (`materia_id`, collection); dedup, the in-flight guard, promotion to the front and the cancel-and-reinsert of [0007](../done/0007-background-queue-and-reset.md) all key on the pair. `enqueue_pending` appends one item per matéria missing atividades, then one per matéria missing trabalhos, so the FIFO gives the order the user asked for: the whole app offline for atividades before the first trabalho. The price is up to 78 more requests at one per second, in the background. `⏎` and `r` on the list refresh the active pane's collection.

### Opening the tab fetches a matéria never synced, under the loading wave
On `TabActivated` for trabalhos, the highlighted matéria without a stamp goes to the front of the queue, like `⏎`. While the in-flight item is the highlighted matéria's trabalhos, the pane carries `loading` — covered by the `Loading` wave of [0007](../done/0007-background-queue-and-reset.md) — and the `-loading` class that gives a pane with hidden children the rows the wave needs. Moving the cursor while the tab is open does not fetch: 0007's rule that the cursor never touches the network stands, and the sweep covers the rest.

### The service is mounted with its consumer
`main.py` builds `TrabalhoSyncService` with the three requests, the repository, `materias_db` and `capturas_db`, and passes it to the App in this change, as [0005.1](0005.1-trabalhos-in-the-interface.md) decided: no consumer, no service.

### The `●` mark tracks the sweep, so it covers both collections
It shows while either stamp is missing and clears when the sweep has finished the matéria. Which collection is missing is what the tab's own hint says.

### Keys on the trabalhos table mirror the atividades table
`TrabalhoTable` is a `DataTable` with a row cursor that means focus, not selection: nothing reads it. `focus_pane` dispatches on the active pane, so `→` from the list lands here, `←`/`esc` return to the list, and `→` at the edge enters the debug panel when open, with the same steps from `cli/navigation/`.

### Debug follows focus: the matéria from the list, the row from a table
While the list has focus the panel shows the matéria — raw `salaVirtuais` entry, `Materia` fields — whatever is selected in the panes. While a pane's table has focus it shows that table's row: for trabalhos the cursor row, matched to its `trabalhoEtapas` entry by `id`, with `Trabalho` fields and "Trabalho N" by `ordem`. Entering the debug panel, by `→` or `j`, keeps what was showing. This revises [0010.1](../done/0010.1-selectable-atividades.md), where a kept selection followed you back to the list; the App watches `Screen.focused` and remembers the last source outside the panel.

### Empty states follow the atividades pane, through a shared hint
"⏎ para buscar no AVA" while `trabalhos_sincronizados_em` is `None`; "Esta matéria não tem trabalhos no AVA." when the fetch returned nothing. `AtividadeHint` becomes a shared `Hint` in `cli/hint.py`, since both panes show the same kind of message. Screen text stays Portuguese.

## Open
- Where entregas and the devolutiva HTML go — a third tab, or a detail below the table. Decided when the table exists.
- Anexos and gabarito wait for the captures 0005.1 requires.

## Rejected
- **On demand only, outside the sweep.** The first version of this spec, kept for 0007's cost argument — 78 requests, 39 for matérias with nothing. An empty tab asking for `⏎` on every matéria was friction the sweep removes for free in the background, and the user took the price.
- **Fetching on cursor move while the tab is open.** 0007's rule: the cursor never touches the network.
- **Capturing entregas and etiquetas too.** Their key is the trabalho or the correção, not the matéria; `Captura` would need a new key for a panel that cannot show them yet.
- **`●` meaning "either collection missing".** The sweep never fills trabalhos, so the mark would never clear on 13 matérias.
- **Fetching when the tab opens.** Turns a digit into a network key; `⏎` already is one, and its hint says so on screen.
- **A `Tipo` column.** Dropped at the user's call: `nomeTrabalhoTipo` is not worth the width the name needs.
- **Entregas as extra columns.** A trabalho has several tentativas; the row would widen past the panel.
- **Rendering the etiqueta HTML in the row.** Over a thousand characters with `<br />` and entities ([0005.1](0005.1-trabalhos-in-the-interface.md)).
- **A `selected_trabalho` reactive on the App.** The cursor row is the selection and only the debug panel reads it, so the table answers `selected` on demand.

## What execution corrected
- The consumer got one `_run_sync(item)` with a service lookup by collection instead of `_run_atividades_sync` and `_run_trabalhos_sync`: the two would have been identical but for the service.
- Pane ids double as collection tags and capture resources: `ATIVIDADES` and `TRABALHOS` from `api/capturas/entity.py` name the pane, the queue item's collection and `Captura.recurso`.
- The trabalhos cursor shows only while the table has focus, toggled on focus and blur, so a blurred row highlight never reads as a selection.
- `watch_restantes` had survived the 0009 rename as a watcher of a reactive that no longer existed, so the queue counter never reached the subtitle. It is `watch_remaining` now.
- Switching tabs with debug open re-renders the panel for the new collection, on `TabActivated`.
- The on-demand rule lasted one review: the user asked for the sweep to load trabalhos after every atividade and for the tab to fetch on opening, so those decisions were rewritten before the second round of implementation.
- The first debug version showed the whole body and the matéria; on screen the user wanted the trabalho, so the panel follows the cursor row, matched to its raw entry by `id` rather than by position. A second review made it follow focus instead of selection, so the list shows the matéria again.
- Verified headless with a seeded temporary SQLite: the sweep calling atividades for every matéria before the first trabalho; the `●` mark clearing only after both; the tab fetching a never-synced matéria with the `Loading` cover on while its item is in flight and off when the cursor leaves it; no fetch on cursor move; the service storing two trabalhos, one `Captura` under `trabalhos` and the stamp; two panes on mount; the trabalhos rows reading "aprovado" and "aberta"; `→`/`esc` in and out of the trabalhos table; `1` from the trabalhos table landing on the atividades table; debug on the trabalhos pane showing the `trabalhoEtapas` body; `⏎` and `r` on the trabalhos pane calling only the trabalhos service, and `r` on the atividades pane only the atividades one; a matéria never synced showing the hint and keeping `→` on the list.
