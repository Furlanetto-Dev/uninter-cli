# Copying what a pane is showing

## TL;DR
- `pages/materias/components/copyable.py` holds `Copyable(Widget)`: the `ctrl+c` binding, `action_copy`, the `check_action` that hides the key when there is nothing to copy, the `Copy` message and the toast.
- The widget supplies the content through one overridable property; `DebugColumn` returns its stored JSON, `FieldsTable` returns the selected entity's.
- `check_action` defers to `super()` for anything it does not own, so it composes with [0016.6](0016.6-pane-navigation.md)'s mixin on the same widget.

`FieldsTable` is a `DataTable` and `DebugColumn` a `VerticalScroll`, so the copy behaviour was written twice rather than inherited — and the two copies have already drifted apart in the name of the attribute they read. Part of [0016](../done/0016-cli-components.md); the panel is [0010.2](../done/0010.2-debug-panel-focus-and-copy.md).

## Observed behaviour
- `DebugColumn` and `FieldsTable` each declare `Binding("ctrl+c", "copy", …)`, a `check_action` returning whether the JSON is present, and an `action_copy` that posts `DebugColumn.Copy` and notifies `COPIED`. The bodies match; one reads `self._json`, the other `self.json_text`.
- `FieldsTable` posts `DebugColumn.Copy` — a message class belonging to a widget it does not inherit from — because that is the message the app listens for.
- `DOMNode.check_action` returns `True` by default, so a mixin that calls `super().check_action(...)` for keys it does not own leaves the other mixin's answer intact.

## Decisions

### It lives with the debug panel, not in `cli/components/`
Both copiers are the debug panel's columns, on the matérias page. [0018](../done/0018-pages-and-their-components.md) puts a widget where its only callers are, and copying is not yet something two pages do.

### The content comes from one property, named for what it is
`Copyable` asks the widget for the text to copy and does the rest. Two attribute names for the same thing is what happens when the behaviour has no owner.

### The `Copy` message moves to the mixin
It is the mixin's message, so both senders and the app's handler name the same class. `FieldsTable` borrowing `DebugColumn.Copy` works only as long as nobody copies the pattern into a widget that is not near the debug panel.

### Guards compose through `super()`
Each mixin answers for its own actions and defers the rest. Without that rule the second mixin on a widget silently wins, and a disabled key comes back to the footer.

## Rejected
- **Copying in the app instead of the widget.** The app would have to know which widget is focused and where it keeps its JSON, which is the coupling the message removes.
- **A `Copyable` that reaches into `renderable`.** What is on screen is formatted; what is worth copying is the JSON behind it.
