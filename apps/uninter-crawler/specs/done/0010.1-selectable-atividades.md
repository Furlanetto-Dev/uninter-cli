# Selectable atividades

## TL;DR
- `AtividadeTable` becomes a `DataTable` with a row cursor; the highlighted row is the selected atividade.
- `→` focuses the table, `←` focuses the list; `↑`/`↓` move inside whichever has focus; `d` clears the selection and jumps to the first matéria.
- Debug moves from `d` to `j`, and the panel shows only the selected atividade, or the matéria's own data when nothing is selected.
- Footer labels go English: `r refresh`, `q quit`, `j debug`, `d home`. The matérias sync leaves the footer for the palette as "Reload matérias".

Today the right panel is a dead `Static`, and the debug panel of [0010](0010-modo-debug.md) dumps every atividade at once: finding one item means scrolling a hundred lines. Context in [CONTEXT.md](../../../../CONTEXT.md); one focusable widget in [0004](0004-tui-em-textual.md), the footer-versus-palette rule in [0007](0007-fila-em-background-e-reset.md), names in [0009](../pending/0009-english-code-portuguese-domain.md).

## Observed behaviour
- Textual 8.2.8 `DataTable` binds `←`/`→` for its column cursor; a subclass overrides them. `OptionList` binds neither. Checked in the class `BINDINGS`.
- The `DataTable` cursor stays visible when the widget loses focus, in the `$block-cursor-blurred-*` colours. Checked in its `DEFAULT_CSS`.
- `DataTable` cells do not wrap: a long name gets an ellipsis where the rich Table folded it onto two lines. Read in the source.
- `r` refetches the focused matéria's atividades; `s` refetches the list of matérias. The second only matters when a matéria appears or disappears.

## Decisions

### The table is a `DataTable` with a row cursor, and the highlight is the selection
`cursor_type="row"`, cells as rich `Text` so the colours survive. No Enter: moving the cursor selects, and so does a click. Cost: long names get an ellipsis instead of folding; the full name is one `j` away.

### `←` and `→` move focus between panels; `↑` and `↓` move inside the focused one
`MateriaList` binds `right` to `app.focus_atividades`; `AtividadeTable` overrides `left` with `app.focus_materias`. `→` highlights the last selected row, or the first, and does nothing when the matéria has no atividades or was never synced. Focus and selection are separate: `←` keeps the row selected. Still one focusable at a time, as [0004](0004-tui-em-textual.md) wanted — now two exist, never both focused.

### The selection lives on the App and clears when the matéria changes
`selected_atividade: reactive[Atividade | None]`, set by `RowHighlighted`. Cleared by `d`, by moving to another matéria, and when a refetch drops the row; a refetch that keeps the atividade (same `id`) keeps the selection. Nothing selected means `show_cursor = False`.

### `d` goes home: clears the selection and focuses the first matéria
Always in the footer as `d home`, from the table or the list, debug on or off. It does not close the debug panel; the panel just shows the matéria again.

### Debug moves to `j` and shows only what is under the cursor
`j debug`, still only with the mode on. Atividade selected: the atividades capture meta line, then the single raw `avaliacaoUsuarios[posicao]` next to `Atividade.model_dump()`. Nothing selected: the `salaVirtuais` entry next to `Materia.model_dump()`, plus the atividades meta line so a 404 stays visible. `show_debug` re-runs on every selection change.

### Footer labels are English, and the matérias sync moves to the palette
`r refresh`, `q quit`, `j debug`, `d home`: the palette is already English since 0010, and the footer follows. `s` leaves the footer and becomes the palette command "Reload matérias", described as "Fetches the list of matérias again" — [0007](0007-fila-em-background-e-reset.md) already put the rare things there. Table headers, hints, notifications and the reset modal stay Portuguese for now.

## Rejected
- **`OptionList` with a grid per row.** Keeps folding and matches `MateriaList`, but column alignment needs fixed widths and there is no row event or click model.
- **`Static` with a hand-drawn highlight.** Cannot take focus; reinvents the cursor.
- **Enter to select, cursor only browses.** A second visual state on a table one row wide.
- **`←` clearing the selection.** Makes `d` nearly redundant and flips the debug panel every time you go back to the list.
- **`d` only visible with a selection.** The jump to the first matéria is useful with nothing selected.
- **Keeping `s` bound but hidden.** A key that works and is not shown is a trap; the palette is discoverable.
- **Dropping the matérias sync.** A new semester brings new matérias; the list still has to be refetched.

## What execution corrected
- `RowHighlighted` only fires when the cursor actually moves, so `→` and every table rebuild set `selected_atividade` explicitly; the event handler covers arrow moves alone, and only while the cursor is shown.
- A `DataTable` cannot display a message, so the empty states ("⏎ para buscar no AVA", "sem atividades") moved to a sibling `AtividadeHint` widget that shows when the table hides.
- The headless test caught a bug: a matéria without atividades hid the table without clearing it, and the stale cursor row still counted as the selection. The table is now rebuilt on every matéria change.
- `j` closing the panel only moves focus back to the list when the panel had it; the table keeps focus otherwise.
